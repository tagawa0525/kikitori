# エンジン ⇔ クライアント プロトコル v0

方針: 音声を入れるとテキストイベントが返る、それだけのプロトコルにする。
トグルやホットキーはクライアント側の関心事であり、ここには含めない。
トランスポートは順序保証のあるストリーム（Unix ソケット → 後段で TCP）を
前提とし、プロトコル自体はトランスポートに依存しない。

## フレーミング

全メッセージ共通:

```text
[u32 LE: payload 長][u8: type][payload]
```

テキスト系 payload は UTF-8 の JSON。音声 payload は生バイト列。

## メッセージ型

### クライアント → エンジン

| type | 名前 | payload |
| --- | --- | --- |
| 0x01 | HELLO | `{"version": 0}` |
| 0x02 | START | `{}`（セッション開始。パラメータ上書きは将来ここに） |
| 0x03 | AUDIO | PCM s16le 16kHz mono の生バイト列（任意長のチャンク） |
| 0x04 | STOP | `{}`（セッション終了。進行中の発話を flush） |

### エンジン → クライアント

| type | 名前 | payload |
| --- | --- | --- |
| 0x81 | READY | `{"version": 0, "model": "sensevoice-small-int8"}` |
| 0x82 | PARTIAL | `{"text": "..."}`（進行中の発話の全文。差分ではない） |
| 0x83 | COMMIT | `{"text": "..."}`（確定した 1 セグメント。以後不変） |
| 0x84 | STOPPED | `{}`（STOP 処理完了。これ以降このセッションのイベントは来ない） |
| 0xFF | ERROR | `{"message": "..."}` |

## ライフサイクル

```text
接続 → HELLO → READY → (START → AUDIO* → STOP → …COMMIT* → STOPPED)* → 切断
```

- PARTIAL は約 400ms 周期で送られる。**全文置き換え**（クライアントは
  表示を丸ごと差し替えるだけでよい。追記差分の管理をさせない）
- COMMIT は VAD の区切りか強制分割（max_speech）で随時発生する
- STOP 後、進行中だった発話は COMMIT として届き、最後に STOPPED が来る。
  確定入力（wtype 等）は STOPPED を待ってから全 COMMIT を結合して行う
- 音声形式は 16kHz mono s16le 固定（48kHz からのダウンミックス・
  リサンプルはクライアントの責務。帯域 32 kB/s）

## 設計判断の記録

- **PARTIAL を全文にする**: 差分方式は境界修正（プレフィックスが変わる）の
  伝搬が複雑になる。全文でも高々数百バイトで、400ms 周期なら帯域は無視できる
- **音声を送りっぱなしにする**: VAD はエンジン側。クライアントに発話判定を
  持たせない（薄く保つ。32 kB/s は LAN でも問題にならない）
- **認証はプロトコル外**: Unix ソケットはファイルパーミッション、TCP は
  SSH トンネル / Tailscale を前提とし、v0 では組み込まない
- **キャンセル（破棄して終了）は未定義**: 必要になった時点で type を足す
  （STOP と別の型にする。in-band で拡張できるのが型フィールドの目的）
